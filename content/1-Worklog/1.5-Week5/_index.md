### Week 5 Objectives:

- Distinguish user/group permissions, role trust, and the permissions of an assumed-role session.
- Explain temporary STS credentials and evaluate role access using request context.
- Interpret IP/time conditions, time zones, and the difference between role assumption and subsequent service access.
- Distinguish Security Hub CSPM findings, standards, controls, and security scores.
- Assess AWS Config recording coverage, remediation, and exceptions when interpreting security-check results.
- Explain AWS WAF web ACL scope, rule priority, managed/custom rules, and WCU capacity.
- Evaluate rule logic with representative requests and use Count, metrics, and logs to assess false positives.
- Plan targeted rule overrides, staged enforcement, and reliable WAF log delivery.
- Explain envelope encryption, KMS permissions and key lifecycle, presigned access, and audit coverage with CloudTrail and Athena.
- Relate RPO/RTO to backup coverage, schedules, and retention; distinguish resource restoration, application validation, and test-resource cleanup.

### Week 5 Achievements:

- **Least privilege:** Can distinguish separating EC2/RDS administration from granting only the actions needed. Broad managed policies remain a starting point for analysis rather than proof of least privilege.
- **Trust reasoning:** A same-account user explicitly trusted by a role can be allowed to assume it without a separate identity-policy allow. No direct service permissions is different from an applicable explicit deny.
- **Conditional access:** Can separate an assumption failure from a later API denial. A trust-policy time window is not a daily schedule or a guarantee that an existing session ends at that boundary.
- **Security assessment:** Can distinguish failed controls from missing evaluation data and prioritize findings using severity and resource context. A score increase caused by disabling a control does not demonstrate that the underlying issue was fixed.
- **Coverage and cost:** Can relate findings to the recorder's account, Region, and resource scope. Estimate costs from checks, finding ingestion, automation-rule evaluations, and applicable AWS Config/storage usage.
- **Rule correctness:** Can reason through matching and nonmatching requests without treating one field as a complete AND condition. Count helps assess false positives but does not guarantee that a request is allowed by the whole web ACL.
- **WAF operations:** Distinguish WCU processing capacity from request volume, and use logs to investigate blocking decisions. Configure destination permissions and sensitive-data handling; request filtering complements fixing vulnerabilities in application code.
- **Targeted remediation:** Can distinguish an intended match from the rule that decides the request, then focus false-positive adjustments on the relevant rule. Define expected outcomes and a rollback path before enforcing changes.
- **Delivery troubleshooting:** Can check stream source, name, Region, and destination permissions when logs are absent. Separate delivery latency from rule propagation and verify sensitive-field redaction in the stored records.
- **Access diagnosis:** Can explain why `User-S3` with S3 access can fail decryption, and distinguish an S3-trusted role from the identity using the console. Selecting key administrators does not automatically grant key usage.
- **Audit interpretation:** Can investigate access using configured event coverage and relevant Athena fields. Distinguish the URL signer from its recipient, and assess encryption, authorization, and audit evidence as separate parts of data protection.
- **Recoverability:** Can assess recovery against known data/application checks and the workload's RPO/RTO. Separate successful backup creation, resource restoration, and usable application recovery when interpreting notifications and job status.
- **Automation choices:** Can compare the lab's SNS–Lambda workflow with AWS Backup restore-testing plans, which schedule restores and manage cleanup after validation or window expiry. Application-specific success criteria still need to be defined.
